**C. Co-developer proposals**

- **Roadmap:** close Phase 15, then the immediate integrity release. Run Track B as a separately versioned tooling project, outside the product’s critical path. Phase 16A establishes labels, privacy, cohort identity and evaluation protocol; 16B tests retrieval changes. Separate Phase 17’s model migration from integrity changes so regressions remain attributable. Phase 18 supplies the service foundation; Phase 19 tools depend on the paragraph registry. Phase 20 requires pilot controls. Phase 21 remains optional; Phase 23 requires source authority, temporal metadata and document access controls.

- **Service shape:** one application package with thin CLI and FastAPI adapters around a typed query service. Return explicit answer/refusal/insufficient-evidence/operational-error states, verified evidence references and degradation flags. Enforce disclosure policy before serialization or streaming. Keep ingestion an administrative job, outside the request path. This avoids premature distributed infrastructure.

- **Index lifecycle:** immutable release directories containing Chroma, BM25, paragraph registry and a complete manifest. Build and validate offline; atomically publish one release identifier. Pin each request to that release, drain old readers and retain rollback versions. Repair desynchronisation by rebuilding a candidate release, not mutating the serving index. Treat the existing pickle loader as trusted-local-only.

- **Tracing and audit:** capture request/step IDs, release/config/model/prompt versions, evidence IDs, budgets, errors and verification decisions. Prefer keyed HMACs over public salted hashes for guessable queries. Hash-only logs cannot reconstruct sampled answers; any encrypted evidence retention needs separate authorisation and retention rules. Hash chaining needs an independent checkpoint to detect wholesale rewriting.

- **Agentic boundary:** use a deterministic state machine with typed read-only tools, validated arguments, deduplicated evidence and request-wide budgets covering retries and fallbacks. A sufficiency model proposes further retrieval; it cannot approve unsupported claims. On exhaustion, return an already verified answer or abstain. No open-ended tool execution.

- **Deployment:** single-tenant is sensible for the first firm, but self-hosting transfers patching, backup and incident duties to somebody. Name that operator and support model before external sales. Keep generic multi-document ingestion deferred; validate supported handbook editions explicitly.
